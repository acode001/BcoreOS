# BcoreOS 🚀

> **彻底拉平测试与生产环境鸿沟，清除多发行版历史包袱；实现降低远程升级失败导致设备失联或不可启动的风险的“盲盒式”原子换代。**

[![License](https://shields.io)](https://opensource.org)
[![Platform](https://shields.io)](https://linux.org)
[![Status](https://shields.io)]()

本项目将**系统（引导/内核/驱动/库）与应用连续体**统一定义为 **BcoreOS**。我们致力于讨论并落地不同 BcoreOS 之间的**跨版本用户数据继承、多节点批量差分原子更新、以及影子启动抗掉电安全机制**，最终**赋予个人与团体对整机全栈生态的完整绝对控制权**。

---

## 💡 为什么需要 BcoreOS？（核心痛点与终极目的）

在传统的工业级 IT 运维与集群管理中，由于历史演进，团队往往会陷入**多发行版并行维护的泥潭**与**传统A/B分区空间浪费的困境**：

1. **研发与测试包袱越来越重**：团队被迫同时维护多条完全不同的系统技术栈，哪个都无法彻底丢弃。测试矩阵呈指数级增长，维护的“历史债务”越来越沉重。
2. **调试与故障溯源极度痛苦**：当线上物理机出现由于内核、驱动或底层库引发的诡异异常时，传统的系统无法轻易“降级”或“跨发行版回退”。测试人员无法控制变量，难以确认“该问题在历史某个特定系统版本中是否正常”，导致根本无法定位故障发生的真正原因。
3. **传统 A/B 分区的空间灾难**：传统抗掉电系统要求磁盘双份等额分区，直接砍掉 50% 物理空间。少分配不够用导致系统暴死，多分配用不上导致磁盘容量极大浪费。
4. **环境漂移与黑盒冲突**：由于测试环境与远程生产现场的底层依赖库（如 glibc）、驱动不一致，系统升级极易因为底层冲突引发崩溃。

### 🎯 BcoreOS 的战略使命：
**彻底斩断发行版底层冲突。无论目标机器原来运行的是什么系统，BcoreOS 支持通过集控端一键强刷，直接将其升级/收敛为当前研发决策唯一指定的系统版本！** 从而拉平异构物理集群的底层血统，让测试环境与远程生产现场 100% 绝对一致。

## ✨ 核心特性矩阵

### 📦 1. 终极断代与全栈控制权 (Holistic Control & Consensus)
* **强制收敛单一版本**：打破“Ubuntu 与 CentOS 互不理解、各用各的包管理器”的极端限制，一键覆盖历史遗留系统，强推研发当前决策的标准环境。
* **绝对极客主权**：拒绝厂商生态锁定，100% 交付完整 Root 权限，允许自由变动内核与深度改写驱动。

### 💾 2. 精益存储：500M 弹性空间共享 (Lean Storage Architecture)
* **告别传统 A/B 空间翻倍**：摒弃传统整机双空间设计的存储浪费。BcoreOS 仅给基础宿主常驻层（AOS）分配固定的 **500MB 精简空间**并在其内部实现低开销双空间交互。
* **标准系统单份化**：核心打包的标准系统固件在存储中**仅占有一份单体实例**。
* **数据盘动态共享空间**：唯一的标准系统固件与用户数据盘**完全共享磁盘剩余的全部弹性空间**，数据盘动态共享剩余空间，减少传统固定 A/B 分区造成的空间浪费，彻底终结多分配浪费、少分配不够的静态分区僵化局面。

### ⏳ 3. 逆向时光机与确定性调试 (Reverse Time-Machine & Debugging)
* **跨发行版自由回滚**：支持无视版本高低、无视血统差异的自由降级。即便当前机器已经是最新的 `Rocky Linux 10.1`，集控端依然可以一键将其强刷回老旧的 `CentOS 8.1` 闭环固件包。
* **异常精准溯源**：通过这种无感回滚能力，测试团队可以立刻在完全相同的物理硬件上对比不同历史版本的表现。通过锁定“该异常在某历史版本是否正常”，结合 BcoreOS 100% 二进制对齐的特性，研发能够以最高的确定性，快速找出导致故障发生的底层真实原因。

### 🔄 4. 跨发行版用户数据绝对继承 (Data Preservation)
* **无损心脏移植**：在后台强行全量覆盖、彻底擦除并对齐底层 AOS 基盘的同时，精准剥离并完好保留用户盘数据。跨异构发行版（乃至跨版本逆向降级）升级，亦可完美保留用户业务数据。

### ⚡ 5. 批量差分与集控式灌装 (Bulk & Differential)
* **高并发轻量分发**：通过第三方主机集控端，一键输入多台目标机 IP 与 Root 凭据即可批量并行下发。
* **字节级差分传输**：采用高效差分算法，仅传输变动的数据块，极大释放传输带宽，让集群物理灌装缩短至秒级。

### 🛡️ 6. 极限安全与影子回退 (Fail-Safe & Watchdog)
* **物理级抗掉电保护**：采用双物理根设计，升级包全量在后台向备份系统（闲置槽位）静默写入。升级过程中发生异常断电时，通过保留可启动的旧系统状态，降低升级失败导致系统不可启动的风险。
* **影子尝试启动 (Trial Boot)**：新系统灌装就绪后不立刻执行永久固化，而是进入观察期并触发全自动超时闭环计数。若因硬件不兼容、内核恐慌（Kernel Panic）卡死，超时后自动强行触发硬重启，完美无感回退至老系统，保障生产设备永远不失联成砖。
* **主动确认主动固化**：新系统成功网络直通后，集控端必须在预设时间窗口内发起实质网络动作（如检查版本）进行确认，逾期未达则触发保护性自毁软重启，强制回退。

## 🗺️ 技术架构与流转生命周期
*特别说明:
1.upt 为 BcoreOS 项目定义的升级包格式。
2.“盲盒”指升级包封装了目标系统运行所需的完整启动链、内核、根文件系统及相关组件，使目标机无需依赖原发行版环境即可完成系统替换；该术语为 BcoreOS 项目中的技术概念。*

```text
       ┌───────────────────────────────┐
       │ 研发最新决策 / 需进行回溯的系统│ 
       └───────────────┬───────────────┘
                       │
                       ▼ (如：将最新的 Rocky 10.1 强制回滚至老旧的 CentOS 8.1)
┌────────────────────────────────────────────────────────┐
│ BcoreOS_build 打包工具链                                │
│ └─► 生成 BcoreOS 盲盒业务全量原子升级包 (.upt)           │
└──────────────────────────┬─────────────────────────────┘
                           │ 
                           ▼ (.upt 固件交付)
┌────────────────────────────────────────────────────────┐
│ 第三方主机集控端 (控制台)                                │
│ ├─► 配置多台目标机 [ IP群组 + Root账密 ]                 │
│ └─► 批量并行「差分传输」与网络继承注入                 │
└──────────────────────────┬─────────────────────────────┘
                           │ 
                           ▼ (跨发行版/跨版本逆向强灌)
┌────────────────────────────────────────────────────────┐
│ 远程生产物理机集群 (版本时光机与确定性故障溯源)          │
│ ├─► [存储革新] 500M AOS内部双槽 + 单份固件与数据盘空间共享│
│ ├─► 数据继承：跨大版本/逆向降级过程中，依然无损保留用户盘│
│ ├─► 影子尝试启动 (Trial Boot) ──► 异常自愈               │
│ └─► 结果对比：验证当前异常在历史版本中是否正常，锁定根因  │
└────────────────────────────────────────────────────────┘
```

## 🛠️ 双态交付物规约

BcoreOS 的自动构建流水线支持以下**双态交付物**的产出与流转：

1. **AOS (Abstraction & Adaptation OS) 初始安装基盘**
   * 封装为 **500MB 精炼原始块设备镜像 (.dd)**。
   * **宿主常驻层**：集成通用 Mainline Linux 内核及相应硬件驱动支持，对外物理屏蔽硬件差异，并在 500M 内部低开销实现双空间安全闭环与跨版本双向演进。
2. **BcoreOS 盲盒业务全量升级包 (.upt)**
   * 采用**单体原子包裹 (Combined Payload)**，深度打入引导器(GRUB)、同源内核、应用根文件系统，以及与之绑定的孪生 AOS 镜像。
   * **单体轻量化与可逆性**：升级包对应的标准系统支持向前演进或向后回滚。在目标机上仅维持单份实体，拒绝 A/B 分区的空间翻倍浪费，直通数据盘共享全部剩余空间。

## 🚀 快速开始

> *以下指南指导如何运行集控工具，实现跨发行版的自由演进与回滚。*
特别说明:
1.本项目的远程部署与系统更新功能仅应在拥有合法管理权限或获得明确授权的设备上使用。
2.本项目与 Rocky Linux、CentOS、Ubuntu 等项目无隶属、授权或官方合作关系，相关名称仅用于描述兼容性或技术场景。

### 1. 准备 BcoreOS 升级包 (.upt)
将需要进行对比调试的历史版本（如 CentOS 8.1）环境使用 `BcoreOS_build` 工具链提炼为 `bcoreos_legacy.upt`：
```bash
./bcoreos_build.sh --input /path/to/legacy/centos8.1/rootfs --output ./bcoreos_legacy.upt
```

### 2. 配置当前运行最新系统（如 Rocky 10.1）的目标机列表
编辑 `hosts.conf`，填写远程物理机信息：
```text
# 目标机器IP      SSH端口   Root用户名   密码
192.168.1.101     22        root          YourSecurePassword1
```

### 3. 执行批量逆向强刷回滚
运行集控工具，强制将在线设备回滚至指定历史版本，进行故障因果关系验证：
```bash
./bcoreos_distribute --firmware ./bcoreos_legacy.upt --config ./hosts.conf
```
